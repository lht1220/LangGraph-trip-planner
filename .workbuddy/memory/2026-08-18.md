# 2026-08-18 工作日志

## "假数据/景点123" 根因排查与解决

### 现象
用户输入"杭州"，推荐景点仍是"景点1/2/3"、地图只有背景、无早午餐推荐。

### 根因（两层）
1. **后端缓存 mock 工具未失效**：`amap_mcp_tools.py` 的 `get_cached_amap_tools()` 首次加载失败后会把 `create_mock_tools()` 结果存入模块级 `_cached_tools`，之后只要进程不重启就一直用 mock。用户之前 AMAP_API_KEY 是 9 字符无效值 → 首次加载失败 → 缓存 mock → 换了真 key 但没重启后端 → 仍是假数据。
2. 前端 JS Key 之前也是占位值 `df86`（地图渲染失败，只有背景）。

### 验证结论
- 用户已换真实 Key：后端 `AMAP_API_KEY`（32位）、前端 `VITE_AMAP_WEB_JS_KEY`（32位）、`VITE_AMAP_SECURITY_CODE`（32位）均有效。
- 实测 `get_cached_amap_tools()` 返回 **16 个真实工具**（mock 只有 3 个），调用 `maps_text_search` 关键词"西湖/杭州"返回真实 POI（杭州西湖风景名胜区、typecode 110202 等）。
- 后端 `/api/map/health` → `mcp_tools_count: 16`。

### 关键经验（可复用）
- **改了 `.env` 里的 Key 后，必须重启后端进程**，否则模块级工具缓存不刷新。
- 高德两种 Key 不能混用：后端 `AMAP_API_KEY` = Web服务类型；前端 `VITE_AMAP_WEB_JS_KEY` = Web端(JS API)类型；2021-12 后申请的 JS Key 还需 `VITE_AMAP_SECURITY_CODE`。
- 前端 `.env` 里 `VITE_AMAP_WEB_KEY`（注释"后端使用"）是**无效冗余变量**，代码未引用，可删。

### 当前运行状态
- 后端：`py -3.14 -m uvicorn app.api.main:app --port 8000`（后台 task qZGG27）
- 前端：`npm run dev`（后台 task XJAx8K），访问 http://localhost:5173

## 深层根因：qwen3.7-plus 推理截断导致 fallback 假数据

### 现象
工具已加载 16 个真实工具、`/api/map/health` 正常，但行程生成仍返回"杭州景点1/2"（北京坐标 116.4,39.9）。

### 根因
- 返回的"杭州景点1/2"实为 `_create_fallback_plan()` 的备用计划（trip_planner_graph.py:553）。
- 触发路径：planner Agent（qwen3.7-plus，**推理模型**）用 2000 token 全花在 `reasoning` 上，而 `llm_service.py` 的 `max_tokens=2000` 被吃光 → `finish_reason: 'length'`（截断）→ `AIMessage.content` 为空 → `_parse_trip_plan` 的 `json.loads("")` 报 "Expecting value: line 1 column 1" → fallback。
- 证据：`response_metadata.token_usage` 显示 `reasoning_tokens: 2000`、`completion_tokens: 2002`、`finish_reason: 'length'`。

### 修复
1. `llm_service.py`：`max_tokens: 2000 → 8192`，`timeout: 60 → 180`（推理模型需留足输出空间）。
2. `trip_planner_graph.py` `_parse_hotels`：`item.get("price_range", "")` 在值为 `null` 时返回 `None` 而非默认值，导致 Hotel 解析失败；改为 `item.get("price_range") or ""` 兜底（estimated_cost 同理）。

### 验证结果
修复后行程生成返回真实杭州数据：西湖(120.148,30.242)、雷峰塔、灵隐寺、西溪湿地、河坊街、胡雪岩故居、京杭大运河等，餐食为知味观/楼外楼/新白鹿/外婆家等真实餐厅。

### 关键经验（可复用）
- **推理模型（qwen3.x / deepseek-r1 等）max_tokens 必须放宽**，否则 reasoning 吃光 token、content 为空、finish_reason=length。排查方法：看 `response_metadata.finish_reason` 和 `token_usage.completion_tokens_details.reasoning_tokens`。
- `dict.get(key, default)` 只在 key **不存在**时返回 default；key 存在但值为 `None` 时返回 `None`。解析 LLM 输出的 JSON 时用 `x.get(k) or default` 兜底 null。
- 调试 LangGraph agent 时，`langgraph_agents` 不会自动 import `config`，需手动 `import app.config` 触发 `load_dotenv()`，否则 `OPENAI_API_KEY 未配置`。

## 第二轮 bug：LLM 输出解析容错（导致又回 fallback）

max_tokens 修复后仍偶尔回 fallback，日志暴露两个新问题：

1. **景点解析失败**：高德 POI 原始数据里 `visit_duration` 是空串 `''`、`ticket_price` 是 `'免费'`，pydantic 无法转 int → 景点列表变空。
   - 修复：`trip_planner_graph.py` 加 `_safe_int()` 辅助方法（容错空串/中文/None/float），`visit_duration`、`ticket_price` 用它解析。
2. **行程计划解析失败**：`Extra data: char 3672` —— planner 输出的 JSON 后面追了说明文字，`json.loads` 报错 → fallback。
   - 修复：`_parse_trip_plan` 改用 `json.JSONDecoder().raw_decode(json_str)` 只解析第一个完整 JSON 对象，忽略尾部多余内容。

### 关键经验
- LLM 输出的 JSON 不可信：int 字段可能给 `''`/`'免费'`/null，JSON 后可能跟文字。解析层必须容错（`_safe_int` + `raw_decode`）。
- **`--reload` 在本项目后台启动（Git Bash + 后台 &）环境下不可靠**，改代码后不重载。手动重启后端最稳（不带 --reload）。

### 最终验证
修复后行程生成返回真实杭州数据：灵隐寺(120.10,30.24)、西湖、雷峰塔、河坊街、南宋御街、西溪湿地、良渚遗址等，坐标全部 120.x/30.x。

## 启停脚本（项目根目录）

为让用户自行管理启停，新增两个 **sh 脚本**（Git Bash 运行）：
- `start.sh`：后台启动后端（`py -3.14 -m uvicorn ... --reload`）和前端（`npm run dev`），日志写到 `backend.log` / `frontend.log`。
- `stop.sh`：`netstat -ano | grep ":$port " | grep LISTENING | awk '{print $5}'` 取 PID，用 `powershell Stop-Process` 杀掉 8000/5173。

用法：`./start.sh` 启动、`./stop.sh` 停止、`tail -f backend.log` 看日志。
注意：Git Bash 里 `taskkill //F` 双斜杠在此环境报"无效参数"；杀进程用 PowerShell `Stop-Process -Id <PID> -Force` 最可靠。
