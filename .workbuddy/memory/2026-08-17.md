## 修复 asyncio 嵌套事件循环崩溃（3.3）
- **现象**：首次请求日志报 `RuntimeError: Cannot enter into task ... while another task ... is being executed`，且 `/api/map/health` 的 `mcp_tools_count=0`（真实 MCP 工具加载失败，被 try/except 吞掉降级成 mock）。
- **根因**：`trip` 路由 → `get_trip_planner_workflow()` → `TripPlannerWorkflow.__init__` → `get_cached_amap_tools()` → `asyncio.run(...)` 发生在 uvicorn 已运行的事件循环内，`asyncio.run` 不能嵌套。
- **修复**：`backend/app/tools/amap_mcp_tools.py` 新增 `run_async(coro)`（有运行循环时交独立线程新循环执行，否则 `asyncio.run`），将三处 `asyncio.run()` 改为 `run_async()`。已用 py -3.14 验证两种分支均正常。
- 该修复使真实高德 MCP 工具能正常加载（需 AMAP_API_KEY + uvx 可用）。

## 实测环境与踩坑（重要，可复用）
- **解释器不匹配**：本机 Git Bash 的 `python`/`python3` 指向 WorkBuddy 自带 **Python 3.13.14**（无依赖）；依赖实际装在 Windows `py` 启动器的 **Python 3.14** user site-packages。
- **后果与对策**：Git Bash 直接 `python`/`pip` 找不到 langgraph；`uvicorn` 报 `command not found`。统一用 `py -3.14 -m <模块>` 调用（如 `py -3.14 -m uvicorn app.api.main:app --reload`）；或建 `py -3.14 -m venv .venv` 后激活再用。
- **pip 安装警告均无害**：fastmcp not on PATH、google-api-core/requests 冲突、hello-agents/openai 冲突，均为机器上其他全局包的杂音，与本项目无关；openai 2.23.0 正是本项目所需。
- **LLM 强制**：`validate_config()` 与 `get_llm()` 都校验 `OPENAI_API_KEY`，缺 LLM Key 后端直接启动失败。
- **千问可用**：DashScope OpenAI 兼容 `https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen-plus`/`qwen-max`/`qwen-turbo`。

## 修复 nest_asyncio 导致的 mock 降级（关键！）
- **实测确认**：移除 `nest_asyncio.apply()` 后，真实高德 MCP 工具**成功加载 16 个**（无运行循环 / 有运行循环两种场景均通过，出现 `Processing request of type ListToolsRequest`）。
- **真正根因**：原 `amap_mcp_tools.py` 中 `get_amap_mcp_tools()`/`get_amap_essential_tools()`/`SyncWrapper._run` 三处 `nest_asyncio.apply()` 会破坏 `anyio` 的事件循环检测，导致 `load_mcp_tools` 启动 `amap-mcp-server` 子进程时抛 `anyio.NoEventLoopError: Not currently running on any asynchronous event loop` → 三级降级成 mock 假数据。`run_async` 已解决嵌套问题，nest_asyncio 多余且有害，已彻底移除（含 import）。
- 注：启动子进程的 env 仅传 `{"AMAP_MAPS_API_KEY": key}`，未继承当前进程的代理环境变量；若网络需走代理才能访问高德，子进程可能直连失败（暂未改，待观察）。

## 高德 Key 类型坑（用户当前卡点）
- 后端 MCP 已连通，但高德返回 `INVALID_USER_KEY` → 用户的 `AMAP_API_KEY`（`backend/.env`）不是有效的「Web 服务」类型 Key。
- **两种 Key 不能混用**：后端 `AMAP_API_KEY`=「Web 服务」类型（调 `restapi.amap.com`）；前端 `VITE_AMAP_WEB_JS_KEY`=「Web端(JS API)」类型（浏览器渲染）。
- 检查发现 `frontend/.env` 当前 `VITE_AMAP_WEB_JS_KEY=df86` 明显是占位/截断值（真实为 32 位 hex），前端 key 也无效 → 这解释了"没有地图"。
- **新增前端安全密钥支持**：`Result.vue` 的 `initMap()` 原未设 `securityJsCode`，2021-12 后申请的 JS Key 会因此加载失败。已加 `window._AMapSecurityConfig`（读 `VITE_AMAP_SECURITY_CODE`），并在 `env.d.ts`/`.env.example`/`.env` 增加该变量（默认空，对老 Key 无影响）。
- 用户需自行去高德开放平台申请正确的两种 Key 并填入。
